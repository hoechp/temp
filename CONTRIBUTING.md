# Contributing

Use Python 3.12+. Keep code and documentation in English and preserve attribution to Philipp Kolodziej. Start with [project scope](docs/scope.md) and the [research roadmap](docs/research/roadmap.md).

## Set up and verify

```sh
python -m pip install -r requirements-dev.lock -r requirements-plot.lock -r requirements-arrays.lock
python -m pip install --no-build-isolation -e .
python -m pytest
python -m ruff check .
python -m ruff format --check .
python -m mypy
python tools/check_docs.py
python tools/research_probe.py
python tools/frontier_probe.py
python -m build --no-isolation
```

For packaging changes, also import and run the installed wheel outside the checkout. CI runs the supported Python versions with plotting dependencies so optional graphical controls are exercised.

## Mathematical contributions

1. State the identity, coefficient domain, branches and singular cases.
2. Test against an independent derivation or reference. Small-component accuracy needs componentwise checks; a body-dominated norm can conceal a lost derivative.
3. Keep exact equality, numerical tolerance and geometric equivalence separate.
4. Distinguish noninvertibility, nondifferentiability, branch choice and conditioning. Never replace a zero-divisor error with a silent NaN or pseudoinverse.
5. Update the appropriate guide and release notes. Mark proposed APIs as proposals until they are implemented.

Keep the core dependency-free. Plotting belongs in the optional layer. Avoid mutable mathematical constants and executable input in formula parsers. Parser length/depth limits are calculator guardrails, not an isolation boundary.

## Documentation and evidence

`docs/README.md` is the navigation hub. User guides cover shipped features; `docs/research/` covers gaps, derivations and proposals. New examples need stated model assumptions and independent checks, not unsupported physical novelty or performance claims. Research probes are bounded experiments, not general solvers. Full render reports identify the data used for checked-in figures; they are not automatically regenerated by every code change.

Historical mathematical fixtures are stored in `tests/fixtures`. `tools/legacy_probe.py` and `tools/legacy_extended_probe.py` can recapture them from a separately available Java checkout. The old migration inventory is accessible in Git history and does not constrain the current project scope.

The owner selected 0BSD. Routine development does not add PyPI credentials, automated release publishing or deployment.
